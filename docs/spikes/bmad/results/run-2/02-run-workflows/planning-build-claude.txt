| ## Goal
| 
| The shop keeper records what comes in and goes out, and sees which items are running low, so that stock can be reordered in time.
| 
| ## Stories
| 
| - Story 1.1: Add and remove items
| - Story 1.2: Report items that are low on stock
| 
| ## Requirements & Constraints
| 
| - Items are tracked by name with an integer quantity.
| - The shop keeper can list the items whose quantity is at or below a given threshold.
| - Python standard library only. No third-party dependency.
| - Every behavior is covered by a unit test that runs with `python3 -m unittest`.
| 
| ## Technical Decisions
| 
| - One package, `shelf`, with one module, `shelf/inventory.py`, holding the class `Inventory`.
| - State is a dictionary from item name to integer quantity, private to `Inventory`.
| - An item whose quantity reaches zero stays in the inventory with quantity 0.
| - Invalid input raises `ValueError`. Nothing is printed and nothing is logged.
| - Tests are `unittest` test cases in `tests/`, run with `python3 -m unittest discover -s tests -t .`.
| 
| ## Cross-Story Dependencies
| 
| - Story 1.2 reads the item state that Story 1.1 manages (`add`, `remove`), and relies on zero-quantity items being kept.
