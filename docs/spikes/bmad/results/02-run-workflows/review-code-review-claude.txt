### F1. `low_stock` excludes items exactly at the threshold: **high**, patch
- **Location:** `shelf/inventory.py:29-30`, `quantity < threshold`
- **Evidence:** the spec's intent and AC1 say "at or below" the threshold, and the method's own docstring says the same. Running `add('nails',1); add('glue',5); add('bolts',9); low_stock(5)` returns `['nails']`. The item at exactly 5 (`glue`) is missing.
- **Impact:** a shopkeeper gets no reorder warning for items that have hit the threshold exactly. This is the core purpose of the feature.
- **Fix:** change `<` to `<=`. The fix is unambiguous.

### F2. Negative threshold does not raise `ValueError`: **high**, patch
- **Location:** `shelf/inventory.py:29-30`
- **Evidence:** the spec lists under "Always" that a negative threshold raises `ValueError`, and AC3 repeats it. `low_stock(-1)` returns `[]` and raises nothing.
- **Fix:** validate `threshold < 0` and raise `ValueError`, matching the `_check_quantity` style. The fix is unambiguous.

### F3. Tests do not cover the defects or most of the spec: **high**, patch (test gap)
- **Location:** `tests/test_inventory.py:34-38`
- **Evidence:** the single new test uses quantities 1 and 9 with threshold 5. It never hits the boundary, so it passes with the `<` bug in F1. Nothing tests:
  - a quantity equal to the threshold (F1)
  - AC2, the empty-result case
  - AC3, the negative-threshold `ValueError` (F2)
  - alphabetical ordering of multiple results (AC1)
- The spec says "Every behavior has a unit test", so this is also a constraint violation.
- **Fix:** add tests for: the equal-to-threshold case, multiple matches sorted alphabetically, no matches → `[]`, and a negative threshold → `ValueError`. These tests would have caught F1 and F2.
